# HotPotQA RLM Test

This test evaluates `dspy.RLM`'s ability to handle multi-hop reasoning questions from the HotPotQA dataset using iterative refinement with sub-LLM calls.

## Overview

**File**: `test_rlm_hotpotqa.py`

**Purpose**: Test whether RLM can effectively use its sub-LLM calling mechanism to:
- Break down complex multi-hop questions into manageable sub-problems
- Use iterative refinement to gather and synthesize information
- Answer questions that require connecting multiple pieces of information

## Key Features

### Budget-Aware Configuration
- **Model**: `gpt-4o-mini` (cost-effective)
- **Questions**: 25 questions (in the 20-30 range)
- **Max LLM calls**: 25 per question (reasonable budget limit)
- **Max iterations**: 12 (enough for multi-hop reasoning)

### What RLM Can Do
For multi-hop questions like "What was the population of the city where Woodward Avenue ends in 2010?", RLM can:

1. **Decompose**: Break the question into sub-questions
   - "Where does Woodward Avenue end?"
   - "What was the population of [that city] in 2010?"

2. **Query Sub-LLMs**: Use `llm_query()` to answer each sub-question

3. **Synthesize**: Combine answers iteratively

4. **Verify**: Check intermediate results before submitting

## Configuration Options

Edit the `main()` function to adjust:

```python
NUM_QUESTIONS = 25         # Number of questions to test (20-30 recommended)
MAX_ITERATIONS = 12        # Reasoning iterations allowed
MAX_LLM_CALLS = 25        # Sub-LLM calls budget per question
VERBOSE = False            # Set True for detailed RLM logs
MODEL = "openai/gpt-4o-mini"  # Can use other models
```

## Why Multi-Hop is Challenging

HotPotQA questions require:
- **Multiple reasoning steps**: Can't be answered in one shot
- **Information synthesis**: Combining facts from different sources
- **Context understanding**: Understanding how pieces relate

This makes it an excellent test for RLM's iterative refinement capabilities.

## Cost Estimation

With `gpt-4o-mini` (~$0.15/1M input tokens, ~$0.60/1M output tokens):
- **Per question**: ~5-15 sub-LLM calls × ~500 tokens = 2,500-7,500 tokens
- **25 questions**: ~$0.05-$0.20 total (very budget-friendly)

## Debugging

Set `VERBOSE = True` in `main()` to see:
- Each RLM iteration
- Code generated by RLM
- Sub-LLM queries
- Intermediate results

## Success Criteria

The test passes if accuracy > 20%, but typical results:
- **Good**: 30-50% accuracy
- **Excellent**: 50%+ accuracy
- **Needs tuning**: <20% accuracy

Multi-hop QA is inherently difficult, so don't expect 90%+ accuracy without significant optimization.

## Next Steps

To improve performance:
1. Increase `max_llm_calls` (more budget for complex questions)
2. Try `gpt-4o` or `gpt-4` (more capable but costlier)
3. Adjust the RLM signature to guide reasoning
4. Add few-shot examples to the RLM prompt
5. Implement more sophisticated answer evaluation (F1 score)
